Читать после `00-CONTEXT.md`. Палитра, шрифты, правила и полномочия агента — оттуда.
Реальные тексты и список материалов — в `03-CONTENT.md`.

---

## 1. Цель и критерии приёмки

Сдержанное международное портфолио: наука, инженерия, продюсирование, инструменты. Основной язык английский. Технический вызов — **главная ≤ 14 KB** в сжатом виде, включая весь inline-CSS и inline-SVG, при нуле блокирующих внешних запросов.

Definition of Done:
- [ ] тело ответа главной < 14 336 байт после сжатия; запросов до first paint — 1;
- [ ] Lighthouse mobile: 100 / 100 / 100 / 100;
- [ ] обе языковые версии полны, переключатель сохраняет текущую страницу;
- [ ] статья с `$…$` и `$$…$$` рендерится без JS и без шрифтов;
- [ ] `Cmd+P` на `/cv/` даёт документ, который не стыдно отправить работодателю;
- [ ] сайт полностью работает с выключенным JS;
- [ ] CI падает при превышении бюджета;
- [ ] добавление нового поста = один `.md` файл и ничего больше.

## 2. Стек

| Слой | Решение | Почему |
|------|---------|--------|
| SSG | **Eleventy v3** | нулевой рантайм, полный контроль над разметкой |
| Контент | Markdown + front-matter | |
| Формулы | `markdown-it` + **temml** → **MathML** на сборке | нативно в браузерах, 0 KB CSS, 0 KB шрифтов, 0 KB JS; KaTeX стоил бы ~23 KB CSS плюс шрифты |
| Стили | один CSS, инлайнится в `<head>`, LightningCSS | |
| Картинки | `sharp` → AVIF + WebP + fallback, `loading="lazy"`, явные размеры | |
| SVG | `svgo` | |
| Сборка | `html-minifier-terser`, brotli-предсжатие | |
| CV → PDF | владелец кладёт готовый PDF в `docs/cv/`; агент только копирует в `_site` и проверяет, что ссылка живая | LaTeX-исходник владельца уже даёт нужный результат |

Клиентский JS на сайте: **суммарно до 1 KB**, и только на запоминание выбранного языка. Всё остальное — нет.

## 3. Структура

```
/                     Home (EN)              ≤14 KB
/posts/  /posts/<slug>/
/projects/  /projects/<slug>/
/tools/                                      индекс инструментов
/about/
/cv/                                         HTML-версия + кнопка Download PDF
/ru/…                                        полное зеркало
/feed.xml  /ru/feed.xml  /sitemap.xml  /robots.txt  /404.html
/cv.pdf
```

`/tools/` — обязательный раздел, а не украшение: инструментов будет несколько, и им нужен собственный индекс, чтобы не растворяться среди проектов. Каждая запись: имя, одна строка, статус (`live` / `in development`), ссылка на поддомен.

### 3.1 Header

```
[логотип 24px]   POSTS   PROJECTS   TOOLS   ABOUT   CV          EN · RU
```
- Логотип — inline SVG, ссылка на `/`, заменяет пункт Home.
- Пункты — mono, uppercase, `0.8125rem`, `letter-spacing:.06em`.
- Текущий раздел и активный язык помечаются «штампом» (инверсный блок из `00-CONTEXT §2.3`), не цветом.
- Переключатель языка ведёт на ту же страницу в другом языке; если перевода нет — на индекс раздела плюс строка `Not translated yet`.

### 3.2 Home

```
        ◆   (логотип, ~88px, единственная сплошная масса на странице)

        Stepan Sazonov
        Одна строка о том, чем занимается. ≤140 символов.

        POSTS ──────────────────────────────────────────
        <заголовок>                          2026-07-25
        <заголовок>                          2026-06-20
        <заголовок>                          2026-06-01
                                        All posts →

        PROJECTS ───────────────────────────────────────
        <название>                                 2026
        <название>                                 2025
        <название>                                 2024
                                     All projects →

        TOOLS ──────────────────────────────────────────
        printor        print-scan animator      live
        proxiguesse                    in development

        ────────────────────────────────────────────────
        [ig] [tg] [in] [tel]        printor · proxiguesse
```

Никаких превью-картинок на главной — бюджет. Раздел `TOOLS` на главной обязателен: это то, что владелец хочет показывать миру, и он будет расти.

### 3.3 Footer

- Ряд 1: иконки 20×20, inline SVG, суммарно ≤600 байт после `svgo`: Instagram, Telegram, LinkedIn, телефон (`tel:`). У каждой `aria-label` и видимый `:focus-visible`.
- Ряд 2, крупнее (`1.125rem`, sans, вес 600): `printor` — ссылка на поддомен; `proxiguesse` — со штампом `in development`, без ссылки. Список инструментов в футере генерируется из того же источника, что и `/tools/`, — руками нигде не дублируется.
- Ряд 3, мелко и моно: год, лицензия контента, ссылка на исходники, ссылка на почту.

### 3.4 Списки

`<ul>`, элемент = ссылка-заголовок слева + дата справа моно. Опционально одна строка описания цветом `--ink-2`. Группировка по годам моно-заголовком. Никаких карточек, тегов-«пилюль», превью-картинок.

### 3.5 Страница записи

- H1, под ним моно-строка: дата · время чтения · теги.
- Тело шириной 34rem; `<figure>` может выходить шире колонки, подпись моно.
- Сноски, `<pre>` с горизонтальным скроллом, таблицы, формулы.
- Внизу: «← Posts» и соседние записи.
- У проектов дополнительно: `role`, `year`, `status`, `stack`, `link`, `repo` — выводятся моно-таблицей под заголовком.

## 4. Контент-модель

```
apps/site/content/
├── en/{posts,projects,tools}/*.md, about.md
└── ru/{posts,projects,tools}/*.md, about.md
```

```yaml
---
title: …
date: 2026-07-25
lang: en
slug: dithering-and-quantization   # общий для языковых версий, связывает переводы
description: ≤160 символов
tags: [physics, print]
draft: false
math: true                          # включает temml на этой странице
---
```

- `draft: true` не попадает в прод, но собирается локально (`--drafts`).
- Формулы: `$E=mc^2$`, `$$…$$`. Обязательно проверить: дроби, интегралы, матрицы, векторы, греческие буквы, `\text{}` с кириллицей, уравнение Ландау–Лифшица целиком (оно точно появится в статьях).
- Если MathML где-то окажется недостаточным — план Б: подключать `katex.min.css` **только** на страницах с `math: true`, не глобально.

## 5. Бюджет 14 KB

1. Главная — самодостаточный HTML: критический CSS, логотип и иконки инлайном.
2. Ни веб-шрифтов, ни сторонних скриптов, ни PNG-фавикона (только `favicon.svg`, он вне first paint).
3. CSS пишется под инлайн: без сброса-фреймворка и неиспользуемых утилит. Ориентир 2.5–3 KB до сжатия.
4. Внутренние страницы могут тянуть внешний `style.css`; там цель ≤30 KB на страницу с картинками.
5. `scripts/budget.mjs`: сжимает `_site/index.html`, сравнивает с 14 336 байт, печатает таблицу «страница / raw / gzip / brotli / запросов», ненулевой код при превышении. Вызывается в `pnpm build` и в CI.
6. Перед заявкой в 14kb.club агент проверяет **актуальную методику измерения на их сайте** и приводит скрипт в соответствие, зафиксировав это в `docs/decisions.md`.

## 6. SEO, доступность

- Корректный `<html lang>`, `<link rel="alternate" hreflang>` между версиями плюс `x-default` на EN.
- OG: `og:title`, `og:description`, `og:type`; `og:image` — статический PNG 1200×630, генерируется на сборке, отдельным файлом (вне бюджета главной).
- Семантика: `header/nav/main/article/footer`, один H1, лестница заголовков без пропусков.
- Контраст ≥7:1. `:focus-visible` — 2px обводка `--ink` (цвета нет, поэтому обводка обязана быть заметной по толщине).
- RSS с полным текстом. 404 в той же типографике.
- Обе темы через `prefers-color-scheme`, без переключателя (переключатель = JS = байты).

## 7. Хостинг и миграция домена

Исходники — публичный репозиторий на GitHub в любом случае. Вопрос только в раздаче.

**Рекомендация: Cloudflare Pages.** Причины конкретны, а не вкусовые:
- brotli из коробки — это те самые проценты, которые решают судьбу 14 KB (GitHub Pages отдаёт gzip);
- один репозиторий → сколько угодно проектов и поддоменов; при десятке будущих инструментов это принципиально;
- apex-домен и wildcard-поддомены без плясок с DNS.

**План Б: GitHub Pages.** Работает, но: gzip вместо brotli, и **один кастомный домен на репозиторий** — значит `printor.<domain>` потребует отдельного репозитория или деплоя из Actions в отдельный репозиторий. Терпимо для двух продуктов, неудобно для пяти.

Решение окончательное за владельцем. Агент реализует деплой так, чтобы **смена хостинга была правкой конфига, а не переписыванием**: сборка ничего не знает о платформе, деплой вынесен в отдельный workflow.

Порядок миграции с Vercel, без даунтайма:
1. собрать и проверить сайт локально;
2. поднять проект на выбранной платформе с временным адресом, проверить всё;
3. перенести NS (или добавить записи у текущего регистратора);
4. привязать apex, дождаться сертификата, проверить `www` → apex редирект;
5. только после успешной проверки убрать домен из Vercel.

CI: на PR — build + бюджет + линт; на `main` — деплой. Заголовки: `immutable` на `/assets/*`, `must-revalidate` на HTML, CSP `default-src 'self'`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`.
