## 1. Что строим

Монорепозиторий: персональный сайт-индекс и растущий набор бесплатных локальных инструментов.

| # | Продукт | Адрес | Статус |
|---|---------|-------|--------|
| 1 | **site** | `<domain>` | портфолио, ≤14 KB на главной |
| 2 | **printor** | `printor.<domain>` | первый инструмент: видео → «напечатано и отсканировано» |
| 3 | **proxiguesse** | `proxiguesse.<domain>` | позже, заглушка |
| n | будущие инструменты | `<name>.<domain>` | архитектура обязана масштабироваться |

**printor — первый инструмент, а не единственный и не главный.** Это определяет два решения:

1. Сайт нейтрален по отношению к любому из инструментов. Он не оформлен «под печать», не оформлен «под физику». Он — точный контейнер, в который одинаково хорошо ложится и статья про уравнение Ландау–Лифшица, и продюсерский проект, и инструмент для художников.
2. Каждый инструмент живёт на своём поддомене и может иметь **собственную визуальную подпись**, наследуя от сайта только типографическую систему и монохром. printor может быть «бумажным». Следующий инструмент — каким угодно другим.
3. Поэтому в репозитории есть `packages/shell` — переиспользуемая оболочка инструмента (лейаут, токены, футер, страница `/support`, PWA-манифест, шаблон README и лицензии). Инструмент №3 должен подниматься за день, а не за неделю.

### Манифест (тон всех текстов)

Инструменты такого класса сегодня продаются по подписке. Наши раздаются бесплатно, считаются на устройстве пользователя, не отправляют ни байта на сервер и не требуют аккаунта. Это не маркетинг, а ограничение архитектуры, зафиксированное в спецификации и проверяемое тестом.

## 2. Дизайн-система

### 2.1 Принцип

Сайт — **индекс, а не лендинг**. Ни героя во весь экран, ни фотографии, ни абзаца о себе на первом экране. Одна колонка, список того, что сделано, даты справа. Всё внимание — на структуру и типографику, потому что больше не на что: цвета нет.

### 2.2 Цвет — чистый монохром, акцента нет

```css
:root {
  --paper: #F2F1EE;  /* бумага, нейтрально-тёплая */
  --ink:   #17181A;  /* почти чёрный, чуть холодный */
  --ink-2: #74777B;  /* мета, даты, подписи */
  --rule:  #D2D1CC;  /* хайрлайн 1px */
}
@media (prefers-color-scheme: dark) {
  :root { --paper:#0F1012; --ink:#E8E7E3; --ink-2:#8A8D91; --rule:#2A2C2F; }
}
```

Выделение делается **не цветом**, а тремя средствами: вес шрифта, размер, инверсия. Никаких градиентов, теней и скруглений (`border-radius: 0` глобально).

### 2.3 Signature-элемент: «штамп»

Единственный выразительный жест на сайте — **инверсный блок**: текст цвета бумаги на плашке цвета чернил, как заполненное поле в бланке.

```css
.stamp { background: var(--ink); color: var(--paper); padding: 0 .35em; }
```

Применяется ровно в трёх местах и больше нигде: активный язык, текущий раздел в навигации, статус проекта (`in development`). Стоит ~80 байт и заменяет собой акцентный цвет.

Второй элемент — **логотип как единственная сплошная масса чернил** на странице. Всё остальное — хайрлайны и текст. Логотип у владельца готов, лежит в `apps/site/src/logo.svg`; агент прогоняет его через `svgo`, инлайнит и не перерисовывает.

Третий — **сайт по-настоящему свёрстан под печать**: `@media print` даёт чистый документ, а не «страницу без навигации». Проверяется на `/cv/` и на статье с формулами.

### 2.4 Типографика — только системные шрифты

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", "Courier New", monospace;
```

Ноль байт, ноль запросов, мгновенный первый рендер. Характер даёт не гарнитура, а разделение ролей, и оно держится жёстко:

- **sans** — смысл: заголовки, текст. Заголовки вес 600, `letter-spacing:-0.02em`.
- **mono** — служебный слой: даты, теги, лейблы разделов, номера, подписи контролов. Uppercase, `letter-spacing:.06em`, на две ступени мельче.

Даты всегда в ISO: `2026-07-25`. Это международно однозначно и выглядит как запись в лабораторном журнале, а не как декор.

Шкала (rem): `0.75 / 0.8125 / 1 / 1.125 / 1.5 / 2`. Интерлиньяж 1.55 в тексте, 1.15 в заголовках. Колонка текста — 34rem.

### 2.5 Layout и движение

Одна колонка, левое выравнивание, единая вертикальная ось. Разделы отбиваются mono-лейблом и хайрлайном, а не крупным H2. Карточек нет.

Движение: только `:hover` на строке списка — хайрлайн прочерчивается по ширине колонки (одна CSS-транзиция). `prefers-reduced-motion` уважается. Больше на сайте не анимируется ничего.

## 3. Полномочия агента

Владелец не хочет утверждать каждую мелочь. Правила:

**Агент решает сам, не спрашивая:**
- любые внутренние технические решения: структура модулей, имена файлов, разбиение компонентов, выбор алгоритма, схема состояния, тесты;
- замена библиотеки на лучшую при равной или меньшей цене в байтах и зависимостях;
- вёрстка, интервалы, размеры внутри заданной шкалы и палитры;
- копирайт интерфейсных строк (по правилам тона из §1);
- порядок задач внутри этапа;
- **отклонение от буквы этого ТЗ, если оно вредит результату** — с обязательной записью в журнал решений.

**Агент обязан спросить:**
- изменение палитры, гарнитур или добавление акцентного цвета;
- любой сетевой запрос из printor или любого будущего инструмента;
- превышение бюджета главной (14 KB) или добавление веб-шрифта;
- смена SSG, хостинга, лицензии;
- всё, что касается персональных данных владельца (телефон, почта, ссылки).

**Журнал решений** — `docs/decisions.md`, формат ADR, по 5 строк на запись: дата, решение, альтернативы, причина, последствия. Каждое отклонение от ТЗ — новая запись. Это не бюрократия: через месяц владелец должен понимать, почему код выглядит именно так.

**Если ТЗ противоречит здравому смыслу — прав здравый смысл**, но решение фиксируется письменно.

## 4. Технические правила

1. **TypeScript.** Идентификаторы, комментарии, строки UI, коммиты, README, issues — по-английски. Русский только в `content/ru/` и в этих ТЗ.
2. Conventional Commits, мелкие атомарные коммиты.
3. Каждая новая зависимость сайта требует обоснования в журнале решений. В инструментах лимит мягче.
4. **Никакого серверного кода, ни одного endpoint, ни одного секрета.** Всё статика.
5. Телеметрии нет нигде.
6. **Чужие ассеты не бандлятся.** Скриншоты effect.app — референс поведения, не источник кода и не источник текстур. Текстуры Texturelabs не редистрибутируются. В репо только собственные файлы владельца и процедурная генерация.
7. **Бюджеты — это тесты.** Размер главной и бандла инструментов проверяются в CI и ломают билд.
8. Порядок: сайт целиком до деплоя → потом printor. Не начинать printor, пока сайт не задеплоен и не измерен.

## 6. Решения, принятые владельцем

| Вопрос | Ответ |
|---|---|
| Логотип | готов, SVG, лежит в репозитории, не перерисовывать |
| Шрифты | системные (Arial/Helvetica-класс + Courier-класс через `ui-monospace`) |
| Акцентный цвет | **нет**, чистый монохром |
| Хостинг | GitHub — исходники; хостинг — Cloudflare Pages (см. `01-SPEC-site.md §7`), GitHub Pages как план Б |
| CV | готов, владелец кладёт в `docs/cv/` |
| Текстуры printor | владелец кладёт сам; агент делает процедурные плейсхолдеры и манифест |
| Кейфреймы в printor | v2 |
| Написание бренда | `printor`, строчными, мелким кеглем, без стилизации букв |
| Бюджет printor | **не ограничен 14 KB**, разумная цель ≤300 KB gzip |
